# Agent log

A public record of how this repository is being built: decisions, assumptions and progress. Private notes about the source machine are kept outside the repository.

## Decisions

- **Target:** Ubuntu 26.04, GNOME 50, Wayland, amd64 at first. Other systems are refused with an explanation until someone tests them.
- **Licence:** MIT for the project's own code. Vendored and derived material keeps its upstream licence (see `THIRD_PARTY_NOTICES.md`).
- **Default components:** terminal, workspace, agents (the relay), memory (empty), clipboard, gnome-look. Hardware tuning and personal app or service choices stay outside the default installation.
- **Agent policy:** the installer keeps the target's existing permission policy and model choices. `--agent-policy full-access` is an explicit opt-in that turns off Claude Code's and Codex's approval prompts. Account, trust and project caches are never imported.
- **Memory:** the installer creates the rules, empty indexes, the `ai-memory` helper and its snapshot timer. It never ships notes and never replaces an existing `~/ai-memory`.

## Milestone 1: a sanitized, testable source tree (2026-10-11)

**Layout:**
- `payload/<component>/` holds the setup's own files, readable and grouped by component.
- `vendor/` holds unmodified upstream runtime code: tmux-resurrect, bash-preexec and the Yazi git plugin.
- `licenses/` holds upstream licence texts that are installed next to the code.
- `templates/memory/` holds the empty global memory and the Claude import block.
- `manifests/` holds `components.toml` (components, dependencies, packages, units, GNOME settings), `files.toml` (every installed file and its destination), `third-party.toml` and `public-allowlist.toml`.
- `installer/` holds the manifest reader and the stager.
- `scripts/` holds `import-live.py` (compare with, or import from, a machine running the setup) and `check-public.py` (the publication scan).
- `tests/` holds the existing suites and the new repository tests, run through `tests/run.py`.

**Exported through the manifest:** the Ghostty config and theme, the Claude theme, the shell fragment and inputrc, Starship, Atuin, the bat, glow and micro themes, both Yazi profiles and their plugins, both tmux profiles, the workspace controller and its wrappers, desktop entries, the Nautilus script, the icon, user units, the relay, the memory helper, the clipboard extension and the vendored code with its licences.

**Changes from the running setup:**
- Paths are rendered at install time from `@HOME@`. Units use `%h`. The Claude URL handler takes the target's own `claude`.
- The Yazi sidebar theme is a relative symlink to the main theme.
- Personal fixture names, the Codex client name and a demo sentence were replaced with neutral ones.
- The clipboard extension has a neutral UUID, `clipboard-list@linux-terminal-agents-workbench`, and keeps the same settings schema.
- The Bash fragment only defines the agent wrappers and workspace hooks when those programs are installed.
- `ya`, `yazi` and `nvidia-smi` are found when the program runs, not patched in at install time.
- `ai-memory` now holds a lock (`~/.local/state/ai-memory/index.lock`) from reading the global index until it is written. Before, two links run at the same moment could lose a project's index entry. A deterministic regression test holds the first link between its read and its write while a second starts.
- micro's empty `bindings.json` and the browser defaults were dropped. No browser becomes a dependency.

**Tests:** `tests/run.py` stages the default components into a new scratch home and runs every suite with `HOME` set to it. A suite run directly stages its own home first. No suite can fall back to code installed in the real home.

## Milestone 2: the installer (2026-10-11)

**Entry point:** `./install.sh` is a thin POSIX wrapper over `python3 -I -B`, with `installer/cli.py` behind it.
- **Modes:** `--check` (the default), `--install` and `--rollback BACKUP|last`.
- **Options:** `--only` (requirements added), `--target-home`, `--no-activate`, `--agent-policy full-access`, `--claude-version` and `--codex-version`.

**Modules:**
- `fsops.py`: every read and write walks from the home with `O_NOFOLLOW`. A folder symlink is followed only when it resolves inside the home. A symlink at the destination is replaced, never written through.
- `merges.py`: the merge strategies named in the manifest. Each is repeatable, and `codex-instructions` is new.
- `plan.py`: the complete change list, worked out before anything changes. It covers folders, links, seeds, the compiled schema and `CODEX_HOME`/`CLAUDE_CONFIG_DIR` remapping.
- `transaction.py`: the journal, apply with automatic undo, the interruption check, and rollback with a conflict preflight.
- `desktop.py`: gsettings set/add/remove, user units and caches.
- `packages.py`: missing apt packages and snaps, and the agent CLIs through the vendor installers.
- `preflight.py`: the supported-system check.
- `engine.py`: puts the steps together.

**Fixes from review:**
- **Staging escape:** `stage()` no longer writes through a symlinked `~/.config`. Installation, backup and rollback use the same confined writes.
- **`ai-memory link`:** it now reads the folder's marker inside the lock. Two links of one folder under different names can no longer both succeed.
- **`check-public.py --history`:** it now checks commit authors, committers and messages. Authors need a no-reply address.
- **`import-live.py`:** it runs the publication scan on each proposed file and refuses to write one with findings.

**Assumptions:**
- A real installation is one whose target is the account's own home (from `pwd`). Any other `--target-home` only stages files.
- Default releases for missing CLIs are each vendor's default, `latest`.
- MIME defaults are added only for types the user has not set.
- Rollback leaves `~/ai-memory` files the user has changed since in place.

## Milestone 2, review round (2026-10-11)

**Recovery:**
- A failed or interrupted run now also undoes the step it was on, including GNOME settings and services. Examples are a value written before gsettings failed, or a unit enabled but not started.
- Undoing goes in this order: stop and disable the services the installation started or enabled, restore files, set GNOME values back, then `daemon-reload` again and restart the services that were running before.
- Service enablement changed after installation counts as a conflict, the same as files and settings.
- An automatic undo that leaves conflicts is recorded as `failed`, with `recovery.problems`, and the report says what was not undone. `--rollback … --keep-changed` keeps such changes and restores the rest, so a failed run never leaves a dead end.

**Order:** every file change is worked out before any package or agent CLI is installed.

**Staging:** an explicit `--target-home` always means staging. The account's home and its ancestors are refused there.

**Publication scan:** secret matches are redacted in reports. Forbidden file names are also checked in history.

**Claude hooks:** deduplicated by event, matcher (empty, missing or `*` all mean "every tool"), hook type and command.

**Agent installers:**
- Before running a downloaded script, the installer checks it against a reviewed interface (`packages.CONTRACTS`) and refuses one that has changed.
- `WORKBENCH_ONLINE=1` runs a test that downloads the current official scripts (never runs them) and checks that interface. It passed on 2026-10-11.
- That test found the vendors' hosts returning HTTP 403 to Python's default user agent. Downloads now send a descriptive one.
